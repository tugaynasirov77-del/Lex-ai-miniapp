# Claude Code Protocol

## TL;DR
- Принцип минимально достаточного контекста: читай ровно столько, сколько нужно для безопасного выполнения задачи.
- Маршрут: CLAUDE.md → 00_HOME → 01_CONTEXT_ROUTER → 1 context pack → код по делу.
- Лимит по умолчанию: 5 заметок Vault + 8 файлов кода до начала работы.
- После задачи обновляй только связанные документы, не весь Vault.

## Когда читать этот файл
В начале любой сессии. После прочтения работай по нему, не возвращайся.

> [!important]
> Этот документ — единый источник правды по протоколу работы Claude Code в LEX AI.

## Принцип минимально достаточного контекста
Claude должен собирать **не максимально возможный**, а **минимально достаточный** контекст для безопасного выполнения конкретной задачи.

Прежде чем открыть файл — задай вопрос: «нужен ли он для текущей задачи?» Если ответ «возможно» — отложи. Если «точно» — открой.

## Алгоритм работы

```
1. Определить тип задачи.
2. Найти тип задачи в CONTEXT_ROUTER.
3. Прочитать HOME.
4. Прочитать одну основную заметку (или 1-2 при необходимости).
5. Найти связанные файлы проекта в заметке + REPOSITORY_MAP.
6. Прочитать только нужные участки кода.
7. Выполнить задачу.
8. Проверить результат (tsc, ручной флоу).
9. Обновить только затронутую документацию.
```

## Правила

### Что обязательно
- Одна тема → один источник правды (см. список в `CLAUDE.md` раздел «Единый источник правды»).
- Ссылки `[[...]]` вместо копирования содержания.
- Короткий TL;DR в каждой заметке (≤ 8 пунктов).
- Все даты в формате `YYYY-MM-DD`.
- Предположения помечаются `Предположение` / `Требует проверки`.
- Актуальный статус хранится в `02_CURRENT_STATE.md`, история — в `CHANGELOG.md`, история решений — в `PRODUCT_DECISIONS.md`.
- Структура репозитория — `REPOSITORY_MAP.md`. Продуктовая логика — `10_Product/`. Не смешивать.
- Документация обновляется одновременно с кодом.
- При конфликте кода и доки — конфликт фиксируется явно в `02_CURRENT_STATE.md`.

### Что запрещено по умолчанию
- Не рекурсивно читать весь Vault.
- Не читать всю папку `docs`.
- Не перечитывать весь репозиторий.
- Не открывать все компоненты.
- Не читать все страницы приложения.
- Не загружать историю Git без необходимости.
- Не повторно читать уже изученные в текущей сессии файлы.
- Не читать длинный документ целиком, если нужная информация в одном разделе.
- Не копировать одинаковую информацию в несколько заметок.
- Не создавать огромные универсальные документы.
- Не сохранять полные логи диалогов и чатов.
- Не делать повторных объяснений стабильных решений.

### Большие файлы
Для `lib/api.ts` (~900 строк), `components/screens/ProjectScreen.tsx` (~700 строк), `lib/lexAI.ts` (~1500 строк):
1. Сначала определи структуру (Grep + список функций/секций).
2. Найди ключевое слово.
3. Прочитай только нужный диапазон (Read с `offset`/`limit`).
4. Не загружай целиком.

## Бюджет контекста (по умолчанию)
- ≤ 5 заметок Vault до начала работы.
- ≤ 8 файлов кода до начала работы.
- TL;DR → нужный заголовок → раздел. Полный документ — только если необходимо.
- При локальной задаче — не читать продуктовую документацию целиком.

Если лимит нужно превысить — кратко объясни причину в текстовом сообщении.

## Формат отчёта

### Перед началом реализации
```text
Контекст задачи:
- Прочитано: <список заметок и файлов>
- Будут изменены: <список>
- Не требуется читать: <список>
```

### После выполнения
```text
Результат:
- Изменено: <список>
- Обновлена документация: <список>
- Не затронуто: <список>
- Следующий логичный шаг: <одна фраза>
```

Отчёт должен быть **коротким**.

## Какие документы обновлять после задачи

| Что изменилось | Обновить |
|---|---|
| Реализована новая фича | [[10_Product/FEATURES]], [[02_CURRENT_STATE]], [[40_Development/CHANGELOG]] |
| Принято продуктовое решение | [[10_Product/PRODUCT_DECISIONS]] (DEC-NNN) |
| Изменена архитектура / новый файл | [[30_Technical/REPOSITORY_MAP]], [[30_Technical/ARCHITECTURE]] (если значимо) |
| Изменены тарифы / лимиты | [[10_Product/MONETIZATION]], [[30_Technical/DATA_AND_STATE]] (если схема) |
| Изменена БД (миграция) | [[30_Technical/DATA_AND_STATE]] |
| Новая интеграция | [[30_Technical/INTEGRATIONS]] |
| Изменён текст UI | [[20_UX_UI/UX_COPY]] |
| Изменён нав-бар / новый экран | [[20_UX_UI/SCREEN_MAP]] |
| Изменён ближайший план | [[03_NEXT_ACTIONS]] |
| Обнаружен баг | [[40_Development/BUGS]] |
| Фикс бага | [[40_Development/BUGS]] (перенос из «открытые» в «закрытые») |
| Любая значимая правка | [[40_Development/CHANGELOG]] |

**Не нужно** обновлять весь Vault после каждой правки.

## Командное разделение (LEX AI)
- Пользователь (Антон) + напарник: вкладки **Создать** и **План** (+ связанные компоненты и инфра, нужная для этих вкладок).
- Главный разработчик: вкладки **Главная** и **Профиль**, общая инфра (биллинг, paywall, аналитика, уведомления, post-publish, разборы как сервис).

При сомнениях, в чьей зоне задача — спрашивай.
