# Prompt Library

## TL;DR
- Шаблоны промптов для повторяющихся задач. Каждый напоминает Claude читать только нужный context pack, не сканировать репо, обновить документацию.

## Когда читать этот файл
При формулировании задачи для новой сессии Claude Code. Скопируй подходящий шаблон, подставь конкретику.

## Шаблон 1 — Добавление новой функции

```text
Задача: <название функции>.

Контекст:
1. Прочитай только Pack: NEW_SCREEN (или ближайший подходящий) из [[60_AI_Workflows/CONTEXT_PACKS]].
2. Не сканируй весь репозиторий.
3. Не читай документы вне pack.

Что сделать:
- <описание желаемого результата>
- Файлы, которые ожидаются к изменению: <список или "определи по REPOSITORY_MAP">.
- Сохрани текущую архитектуру (FlowProvider, AppFlow роутинг, StateBlock для empty/error).

После выполнения:
- npx tsc --noEmit чисто.
- Обнови [[02_CURRENT_STATE]], [[10_Product/FEATURES]], [[40_Development/CHANGELOG]].
- Не изменяй несвязанные части проекта.
```

## Шаблон 2 — Исправление UI

```text
Задача: <описание визуального бага>.

Контекст:
1. Pack: UI_BUG.
2. Не читай монетизацию и маркетинг.

Что сделать:
- Файл: <компонент>.
- Используй константы из [[20_UX_UI/DESIGN_SYSTEM]].
- Если нужен empty/error — [[Components/StateBlock]].

После:
- tsc чисто.
- Обнови [[40_Development/CHANGELOG]] коротко.
- Если правил [[20_UX_UI/UX_COPY]] — обнови документ.
```

## Шаблон 3 — Исправление бага

```text
Задача: Баг — <симптом>.

Контекст:
1. Pack: UI_BUG или API_WORK (по типу).
2. Прочитай [[40_Development/BUGS]] — возможно уже заведён.
3. Не читай продуктовые заметки.

Что сделать:
- Найди корень (не симптом).
- Минимальный фикс.

После:
- tsc чисто.
- Если баг был в [[40_Development/BUGS]] — перенеси в «Закрытые».
- Если новый — добавь запись в «Закрытые» с датой.
- [[40_Development/CHANGELOG]] — короткая запись.
```

## Шаблон 4 — Изменение onboarding

```text
Задача: <правка welcome / Quick Setup / OnboardingSuccess>.

Контекст:
1. Pack: ONBOARDING.
2. Прочитай [[10_Product/PRODUCT_DECISIONS]] DEC-001, DEC-002, DEC-005.
3. Не читай Plan, биллинг.

Что сделать:
- Учти все три состояния гейта (localStorage + server flag + наличие проектов).
- Не ломай существующих 341 юзера (welcome им не должен показываться).

После:
- tsc чисто.
- Обнови [[10_Product/ONBOARDING]], [[02_CURRENT_STATE]], [[40_Development/CHANGELOG]].
- Если изменилась продуктовая логика — добавь DEC-NNN в [[10_Product/PRODUCT_DECISIONS]].
```

## Шаблон 5 — Изменение монетизации

```text
Задача: <изменение тарифа / paywall / квоты>.

Контекст:
1. Pack: MONETIZATION.
2. Прочитай DEC-003, DEC-004, DEC-005, DEC-006.
3. Не читай UX-копи всего проекта.

Что сделать:
- Источник правды по тарифам — `lib/tiers.ts`. Сначала меняй там, потом синхронизируй [[10_Product/MONETIZATION]].
- Учти whitelist админов в `lib/gating.ts`.

После:
- tsc чисто.
- Обнови [[10_Product/MONETIZATION]] и `lib/tiers.ts`.
- Если новое решение — DEC-NNN.
- [[40_Development/CHANGELOG]].
```

## Шаблон 6 — Рефакторинг

```text
Задача: Рефакторинг <области>.

Контекст:
1. Pack: соответствующий теме (REELS_ANALYSIS / CREATE_TAB / …).
2. [[30_Technical/TECHNICAL_DEBT]] — найди соответствующий пункт.
3. Не читай маркетинг.

Требование:
- Поведение НЕ меняется. Diff только структурный.
- Если убираешь legacy — grep подтверждает, что не вызывается.

После:
- tsc чисто.
- Обнови [[30_Technical/TECHNICAL_DEBT]] — статус пункта.
- [[40_Development/CHANGELOG]].
```

## Шаблон 7 — Аудит экрана

```text
Задача: Аудит экрана <ScreenKey>.

Контекст:
1. Pack: NEW_SCREEN.
2. Конкретный компонент из [[20_UX_UI/SCREEN_MAP]].
3. [[20_UX_UI/DESIGN_SYSTEM]], [[20_UX_UI/UX_COPY]].

Что проверить:
- Все empty/loading/error используют StateBlock.
- Тексты соответствуют [[20_UX_UI/UX_COPY]] (нет «канала», «бота», «гайда»).
- Отступы и радиусы по DESIGN_SYSTEM.
- Mobile-first.
- Нав-бар не перекрывает контент.

После:
- Список найденных несоответствий (без правок!) в виде заметок.
- Если правки — отдельная задача, ссылка на этот аудит в PR.
```

## Шаблон 8 — Обновление базы Obsidian

```text
Задача: Обновить Vault после <события>.

Контекст:
1. Открой только заметки из таблицы «Какие документы обновлять» в [[60_AI_Workflows/CLAUDE_CODE_PROTOCOL]].
2. Не читай весь Vault.

Требование:
- Никакого дублирования.
- TL;DR обновить если содержание изменилось значимо.
- Обновить `updated:` в frontmatter изменённых документов.
- Все ссылки `[[...]]` ведут на существующие файлы.

После:
- Не нужно tsc.
- [[40_Development/CHANGELOG]] раздел «Документация».
```
